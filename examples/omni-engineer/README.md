# Ejemplo · Omni Engineer

Este directorio documenta **Omni Engineer** como un ejemplo de codebase real dentro del Diplomado.

El código original del proyecto permanece en la historia de este repositorio y en la rama `main`. En la rama `diplomado`, lo estudiamos como **objeto de aprendizaje**, no como currículo principal.

## ¿Qué observamos?

1. **README como mapa del proyecto** — explica qué hace el software y cómo usarlo.
2. **`main.py` como codebase ejecutable** — muestra una aplicación real construida alrededor de modelos y herramientas.
3. **`requirements.txt`** — declara dependencias.
4. **`.env.example`** — enseña la separación entre configuración pública y secretos.
5. **Comandos** — muestran cómo una interfaz puede convertir intención humana en acciones sobre archivos, búsqueda, imágenes y ejecución.

## Preguntas para tus agentes

Pídeles que investiguen el codebase y regresen con respuestas verificables:

- ¿Qué puede hacer Omni Engineer?
- ¿Qué archivos son esenciales?
- ¿Dónde están las dependencias?
- ¿Qué acciones requieren secretos o credenciales?
- ¿Qué partes son interfaz y cuáles son ejecución?
- ¿Qué riesgos tendría ejecutar el proyecto sin revisarlo?
- ¿Qué cambiarías para hacerlo más accesible a una persona que nunca ha programado?
